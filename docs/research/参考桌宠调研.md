#### A3. 表情与反应

参考项目**没有表情系统**，因为是整段预渲染的视频。它的"反应"全是整段动画：

- 点击回应 3 种：开心跃动、害羞惊讶、傲娇生气。
- 被吓一跳、打瞌睡被惊醒、偷吃零食被抓住等放在随机池里。
- 点击时叠加一次程序化"Q 弹"挤压，`SQUASH_DURATION_MS=220`（`pet_sprite.py:45`）。
- 音乐唱歌：检测到后台在放音乐就循环播"悠闲哼歌"（`SING_ANIM`，`window.py:115`）。
- 动作池里还有按时间或事件选的素材，比如吃早餐、吃午餐、吃晚餐、被落叶淹没、堆雪人。

碰撞参数摘要（`collision.py:24-57`、`sprite_collision.py:89-116`）：

- 恢复系数 0.82，摩擦 0.08，质量倍率 1.0，冲量上限 9000px/s。
- 接近速度低于 80px/s 只做位置分离。
- 命中阈值 dv 300px/s，撞静态布景放宽到 60。
- 撞灵动岛的静态恢复系数是 1.3（"弹床"）。这个参数被点名是"能量泵"的根因，所以只在动态方尚未抛掷时才生效。

| 隐藏时 | 隐藏桌宠即暂停解码和活动定时器，CPU 接近 0 |
| 性能治理 | 首帧缓存、预测预热、ffmpeg 回收……都是解码问题，3D 不涉及 |

### B. 状态机与互动细节

#### B1. 动作选择（`sprite_behavior.py`）

状态：`idle`、`move`、`turn`、`click`、`acts`、`drag`、`thrown`（`:132-141`）。只有 `interaction_state == normal` 时才跑掷骰链；拖拽和抛掷期间位置归鼠标和物理，行为层只负责"该播什么画面"。

**掷骰**（`_roll_next`，`:1369-1405`，概率在 `catalog.py:36-39`）：

1. 触发时机是上一段 **idle 播完**，或 **acts 播完**。move 播完则先进 gap 或回 idle。
2. `roll = random()`：`<0.30` 待机，`<0.40` 转向，`<0.80` 随机动作，否则移动。
3. 移动被拒绝（`no_move`、两侧空间都不足 `MOVE_MIN_PX`、探头中）就回退到随机动作，动作池为空再回退待机。
4. **朝向闸门**：朝向**绝不由随机数翻转**。
   - 掷中转向但朝向已对，降级为待机。
   - 掷中待机但朝外且有转向素材，改播转向。
   - 朝向判据 `inward_facing`（`movement.py:82-100`）：以可达带中线为界，**中线两侧各 7% 可达带宽度为滞回带**，带内不纠正。
5. **防重复**：`_pick(pool, exclude=st.anim)`（`:1800-1804`）只排除"上一个播的 clip"；池里只剩一个时回退为全池。**没有"最近 N 次"历史**。

**移动**（`_plan_move`，`:1544-1606`）：

1. 方向：两侧剩余空间都 ≥ 60px 才随机二选一，只有一侧够就走那一侧，都不够则不移动（`choose_move_direction`）。
2. 距离 = `randint(60, min(240, 剩余空间))`；屏幕边缘边距 20px。
3. 然后**量化为步态整圈**：圈数 = `max(1, round(距离/步幅))`，越界就递减。步幅默认 120px，可由素材覆盖。**速度 = 位移/时长，所以速度恒等于步态速度，不脚滑**。
4. Y 方向也随机漫游，幅度 ±max(40, 可用高度×25%)。
5. 需要反向时：**先播转向，播完才翻 facing**，再执行排定的移动（`pending_move`）。

**动画间隔**（`animation_gap_seconds`，默认 0 = 关）：

- 动作或移动播完后，若大于 0，进入"氛围步"：从 idles+turns 池里取，播完继续取，直到计时到点才回掷骰链。
- 氛围步里掷中转向，同样要过朝向闸门，否则降级待机。
- 点击、拖拽、抛掷接管会立即取消 gap。

**接管规则**：

- 点击：打断任何状态（含上一次点击），选 click 池随机一段（排除当前），播完回待机。无 click 素材返回 False（调用方放行穿透）。
- 拖拽：按下命中即绑 drag 悬空动画（无素材回退 idle），松手回待机池。
- 抛掷：绑 drag 动画循环，播放速率随速度加快：`1 + min(v/1400, 1) × 0.75`，即最高 1.75 倍（`physics.py:101-112`）。
- 接管结束时，接管前排定的移动和转向计划**一律作废，绝不瞬移回原路线终点**（F5）。
- 探头会话期间：只允许待机和转向，移动被闸门拦住，转向播完不翻 facing。

**3D 不需要的部分**（可以放心跳过）：

- ACTS/IDLE/MOVE/CLICK/TURN 的"圈末收口"（`_acts_tail_done` 等）。
- 预测预热、首帧 pin、`move_curves`（圈内逐帧位移曲线）。

### C. AI 对话细节

#### C1. 请求参数

- **端点**：`normalize_chat_endpoint`（`providers.py:89-94`）。默认 `https://api.deepseek.com` + `/v1/chat/completions`；base 已带 `/vN` 就只补 `/chat/completions`；base 本身已以 `/chat/completions` 结尾则原样用。
- **默认 provider**（`config.py:420-438`、`models.py:60`）：
  - 模型 `deepseek-v4-flash`（**我无法核实这个模型名是否真实存在，请用户核对**），超时 60s，temperature 0.7，max_tokens 2048。
  - 历史条数上限 40，历史字符上限 24000。
  - `verify_ssl` 默认 True，用 certifi 的 CA 包。
- **流式请求体**（`_stream_answer`，`providers.py:235-238`）：`{model, messages, stream:true, temperature, max_tokens}` + 可选思考参数。
  - 思考 `thinking` 三态 `auto/enabled/disabled`。`auto` 时**只对 deepseek.com 地址发思考参数**，避免严格校验参数的服务报错。
  - 开启时发 `{"thinking":{"type":"enabled"},"reasoning_effort":"low|high|max"}`，默认 `high`。
- **请求头**：伪造浏览器 UA（`Chrome/126`）、`Accept-Language: zh-CN`，目的是降低 Cloudflare 1010 误判（`providers.py:47-62`）。
- **实现**：直接用标准库 `urllib`，没有第三方 HTTP 库。

#### C2. System prompt 拼装（`prompt.py:89-139`）

从前到后依次拼接（后面的 `\n\n` 追加在前面之后）：

1. **人设**，优先级：角色用户自定义 prompt > 角色 `manifest.json` 的 `chat.system_prompt` > 全局默认。全局默认是"你是一只可爱的桌面宠物，请用自然、友善的中文和用户交流。"
2. **场景扮演引导 + 场景卡**：仅当 `roleplay_enabled` 且 system 非空时追加。引导共 8 条（场景要活、旁人有动静、每轮推进一步、不替用户做决定等，`prompt.py:24-42`）。
3. **时间感知段**（`_TIME_NOTE`）：`【时间信息】当前时间：{YYYY-MM-DD 周X HH:MM}。` 如果距上一条消息 ≥ 10 分钟，追加"距离上一条消息（…）已经过去约 X 天/小时/分钟。"，并告诉模型"用户消息开头的 `[日期 时间]` 是系统附加的，不要复述或模仿"。
4. **用户层记忆快照**（`user` 层，≤600 字）。
5. **按需命中的记忆**（`fact/lesson/topic`，用本次真实用户消息检索，首轮不命中，top 3、≤600 字）。

**历史消息**：用户消息前加 `[YYYY-MM-DD 周X HH:MM] ` 前缀，助手消息不加（防止模型学着在回复里写时间）。时间只在发给模型时附加，不改动落盘的会话。最后追加本次用户消息（`strip()`）。

**联网搜索**结果再追加到 system 最末（`inject_search_context`，含"优先采用资料中的最新信息""末尾列参考来源"）。

#### C3. 上下文裁剪（`PromptBuilder.trim_history`，`prompt.py:140-148`）

从最新往旧倒着取，直到条数 ≥ `history_message_limit` 或累计字符 > `history_char_limit`（下限 100）就停。只要结果非空，超限的那条就整条丢掉。结果为空时，只取最新一条并保留其**尾部** `limit` 个字符。**system 提示词和当前用户消息不计入额度**。

#### C4. 流式解析

- `SSEParser`（`providers.py:99-134`）：按 `\r\n\r\n` 或 `\n\n` 切事件；缓冲上限 1MB，超过抛 `ProviderError`；跳过空 `data:` 心跳行；`[DONE]` 置 `done`；`delta.reasoning_content`（或 `reasoning`）解析为思考过程，`delta.content` 为正文；记录 `finish_reason`。
- 流式事件以 `StreamEvent(kind, text)` 区分 `reasoning` 和 `status`，正文仍以 `str` 产出。
- 线程模型：`QThread` 里跑 `provider.stream`，信号**显式 `QueuedConnection`** 回 GUI 线程，用 `request_id` 防止旧请求污染新会话（`service.py:109-127`）。
- UI 打字机：每个 tick 从 `_pending_output` 里取 `max(1, min(10, (len+39)//40))` 个字符，大块 SSE 也逐字显示。最终文本与已显示不一致时，回退到公共前缀重打（`widgets.py:2450-2499`）。
- 停止：未完成的半截回复**不保存**。

#### C5. 错误处理与文案

- **HTTP 错误**：`ProviderError("HTTP {status}: {msg}")`。`msg` 来自响应 JSON 的 `error.message`，否则取原文压缩空白截 300 字（`_safe_error_detail`，`:337-342`）。
- **网络错误**：`网络连接失败：{reason}`；若判断为证书问题（`ssl` / `certificate` / `tls`）追加提示"可在 AI 设置中勾选'跳过 SSL 证书验证'后重试"。
- **空回复**：`模型未返回任何内容，请稍后重试或检查模型配置。`
- **思考吃光额度**：只有 reasoning、没有正文、`finish_reason=length` 时，提示"深度思考用完了'最大输出 Token'（当前 N），请在 AI 设置 → 生成参数里调大（建议 8192 以上）"（`:256-257`）。
- **UI 展示**：气泡内容 `请求失败：` + 原文，状态置 error，桌宠气泡显示前 80 字。
- **认证错误检测**：字符串匹配 `401/403/unauthorized/authentication/api key/认证失败/未授权/授权`，命中则发系统通知"需要授权…点击打开 AI 设置检查 API Key"（`widgets.py:2402-2408`）。
- **注意**：`402 / 429 / 5xx` 在**代码里没有特殊处理**，只是原样显示 HTTP 错误文本。"常见错误码"那张表（401/403 Key 无效、402 余额不足、429 限流、5xx 服务端故障）只存在于 README，是给用户看的说明。
- 联网检索失败只降级：第一轮失败显示"联网检索不可用（…），将直接回答"，然后正常回答。

#### C6. API Key 存储（`models.py:134-215`）

- `SecretStore`，服务名 `dsh-pet-standalone`，条目名 `provider/<provider_id>`（联网搜索用 `websearch/api`）。
- 可用性探测：`import keyring` 成功**且**后端不是 `keyring.backends.fail/null` 占位类。按**全名精确匹配**加类身份检查，**不扫名字子串**（子串匹配曾误杀合法第三方后端）。
- 读写失败只记 warning 日志，只记异常类型名，不记 key。
- **回退**：`keyring` 不可用时 `get/set` 返回空/False，API Key 只能留在内存。README 说"可按设置选择配置文件回退"，而 `config.py` 的注释说"`_redacted_data` 不落盘、明文只存在内存里"。**两处说法有出入，我没读保存路径去核实。**
- 恢复默认设置**唯一保留的就是 API Key**（`config.py:483-490`）。
- 已知坑：打包版曾漏带 `keyring`（见 E）。

#### C7. 会话存储格式（`models.py:117-123`、`session_store.py`）

```json
{
  "session_id": "<uuid hex>", "character_id": "...", "provider_id": "...",
  "system_prompt": "...", "created_at": "ISO(UTC)", "updated_at": "ISO(UTC)",
  "title": "", "pinned": false,
  "messages": [ { "role": "user|assistant", "content": "...",
                  "created_at": "ISO(UTC)", "message_id": "<uuid hex>",
                  "reasoning": "(非空才写)", "activity": ["(非空才写)"] } ]
}
```

- 路径 `<配置目录>/sessions[-slotN]/<character_id>/<session_id>.json`；同目录的 `memory.json` 是记忆文件，`list()` 里被排除。
- **异步写盘**：单线程 writer 队列，`temp + fsync + os.replace` 原子替换，替换冲突按 0.05/0.1/0.2/0.4/0.8 秒退避重试。读时 **pending 层优先**（read-your-writes）。
- 读失败（损坏）：文件改名为 `.corrupt-<unix时间戳>.json`，返回 None。
- 追加消息走"读 → 追加 → 提交"一次原子操作，防多前端互相覆盖。
- 会话标题优先用自定义标题，否则取第一条用户消息前 24 字，否则"新会话 · HH:MM"。

#### C8. 记忆（`chat/memory.py`、`memory_recall.py`、`memory_extract.py`）

四层：`user`（恒注入）、`fact`、`lesson`、`topic`（后三层按需命中）。

| 项 | 值 |
|---|---|
| 存储 | 每角色一个 `memory.json`，上限 100 条 / 4000 字符，单条 500 字符。超限按 hits 少 + 最老淘汰 |

| 命中 | 关键词（中文 bigram）+ BM25，半衰期 14 天，每次最多 3 条、≤600 字；topic 连续 14 天未命中自动归档 |
| 自动提炼 | 后台静默调用同一 provider，**每 5 轮、间隔 ≥30 秒**，用户消息有效字符 ≥4，输出最多 8 条 ADD/UPDATE/FORGET，每条文本 ≤200 字。这部分我只读了常量，没读提示词细节（`memory_extract.py:44-69`）【未读细节】 |
| 开关 | `chat_memory_enabled`，关则零成本 |
| 并发保护 | 三层锁（跨进程 QLockFile、进程内宽锁、本地 I/O 窄锁），因为设置页是独立进程 |

#### C9. 联网搜索（`providers.py:164-335`、`web_search.py`）

- 单独先走**非流式、非思考**的"规划"请求，带 `web_search` 和 `fetch_url` 两个工具，让模型决定搜不搜。最多 3 轮、每轮最多 4 个调用，笔记总字数上限 24000，网络超时 5–20 秒。
- 引擎：`baidu`（默认，免 Key）、`duckduckgo`、`bocha`、`tavily`（后两者要 Key）。免 Key 引擎之间互为回退。

#### C10. 与桌宠联动

`PetChatLink` 只通知桌宠窗口：`thinking` →气泡"正在想怎么回答…"；`streaming` →气泡显示前 60 字；`success`；`error`→前 80 字（`chat/pet_link.py`）。`set_chat_status` 只弹一个 2.2 秒气泡，**没有切换动画**。README 提到角色 manifest 里可声明 `chat_actions: {thinking, success, error}` 动画，我没追到消费代码，不确定是否真实现。

### D. 对 Usagi 3D 桌宠的映射建议

先说一个前提：参考项目的"动画"是预渲染视频片段，Usagi 是 VRM。Tripo 出的模型**自带没有动画**，所以"待机/走路/点击"这些都要自己做，有两条路：

- **程序化**：正弦驱动骨骼，做呼吸、耳朵晃、头部看向、弹跳。
- **VRMA 动画片段**：`@pixiv/three-vrm-animation` 加载，可以从 Mixamo 重定向，也可以用 Blender 自己 K 帧。**我没核实这个包当前版本的 API，这是依据已有知识的建议。**

建议 MVP 阶段**全部程序化**，不依赖外部动画素材。下表第 3 列是"在 3D 里怎么做"；标 🪟 的是依赖 Windows 专有能力、mac 上做不了或要换实现的项。

| 参考项目功能 | 分级 | 3D / Electron 实现 |
|---|---|---|

### E. 值得注意的坑（对 Electron 方案仍适用的部分）

下面每条标了出处。"适用性"是我的判断，不是参考项目的结论。

1. **透明窗 + 逐像素穿透：看得见点不到**（`***.md`）
   - 根因：按下事件设了 `_mouse_grab`，但丢了 release（alt-tab、模态抢焦点、屏迁移），grab 永久卡住，整窗穿透再也退不出去。
   - 参考项目的修法：加看门狗，发现"没有按下但 grab 还在、且左键已不在按下态"就强制收尾；穿透态收敛要有"无闸即清"的通道。
   - **适用**：Electron 里 `setIgnoreMouseEvents(true, {forward:true})` 加自己的命中检测，同样会遇到"状态与现实脱同步"。**所有穿透状态都要有定时对账（比如显示/恢复/输入到达时重新判定），不要只靠事件驱动。**

2. **macOS 抢输入法焦点**（`***.md`）
   - 症状：用户拼音没打完，桌宠突然抢走主窗口焦点。
   - 根因：每 30 秒的"置顶保活"在 mac 上调了 Qt 的 `raise_()`，会激活 accessory 应用。
   - **适用**：Electron 里不要周期性调 `win.focus()` / `win.show()` / `moveTop()` 来"保活置顶"；窗口设 `focusable:false`（mac），`showInactive()` 代替 `show()`。置顶用 `setAlwaysOnTop(true, 'floating'|'screen-saver')` 一次设置，不要反复重申。

3. **macOS 多桌面（Spaces）下桌宠消失**（`***.md`）
   - 症状：把宠物拖到另一块屏的另一个桌面，或切换普通桌面后，窗口 `onscreen=false`。
   - 根因：Qt 默认给工具窗口设 `MoveToActiveSpace` 而非 `CanJoinAllSpaces`。
   - **适用**：Electron 需 `win.setVisibleOnAllWorkspaces(true, {visibleOnFullScreen:true})`。**必须实测切换桌面和进入全屏应用的场景**，参考项目也没验证 Stage Manager 和全屏专属 Space。

4. **macOS Dock 图标重复**（同 `***.md`）：设置窗进程和主进程各出一个 Dock 图标，还往 recent-apps 写了两条。参考项目用 `LSUIElement` 加运行时 Accessory 策略解决。**适用**：我们用同一个 Electron 进程开设置窗，不会遇到；若想隐藏 Dock 图标用 `app.dock.hide()`，但隐藏后要保证托盘图标是恢复入口。

5. **多屏 DPI 与混合缩放**（`RELEASE-v4.3.4.md` #307）
   - 一个窗口只能有一个 `devicePixelRatio`。铺满虚拟桌面的大窗在"主屏 1920×1080@100% + 副屏 3200×2000@200%"下取到 DPR 2.0，主屏的桌宠整只画到可见区之外。
   - **适用**：Electron 窗口很小、跟着宠物走，**天然避开这个问题**，这也是不照搬"一窗铺满全屏"的理由。但窗口跨屏拖动时 DPR 会变，Three.js 的 `renderer.setPixelRatio` 要监听 `screen` 的 `display-metrics-changed` 和窗口移动事件后更新。窗口坐标要用 DIP，不要混用物理像素。

6. **mac 多屏窗口不可见**（`***.md`）：一个跨两块显示器的大窗在副屏上"窗口缓冲有图、用户看不到"。**不能用截图或窗口缓冲当作"可见"的验收证据，必须看真实桌面。** 这条对我们的验收方式有直接意义（M7 要用户亲自走查）。

7. **置顶丢失**：Windows 上资源管理器重启、分辨率/DPI 变更、休眠唤醒会让置顶失效。参考项目每 30 秒自检并重新置顶。**适用**：Windows 上可做低频对账，但**不要在 mac 上这么做**（见第 2 条）。

8. **全屏应用会盖住桌宠**：浏览器 F11、视频全屏、独占全屏游戏都是系统级置顶行为，任何置顶窗口都会被盖住（README 已知限制）。不要承诺能盖过全屏应用。

9. **钥匙串不可用时的诚实处理**（`models.py:170-198`）：模块在不等于后端可用。写入失败时界面如果说"已保存"，重启后就读到空串。**适用**：`safeStorage.isEncryptionAvailable()` 为 false 时，设置页必须明说"本次运行有效，重启后需重填"，不能静默假装成功。另外，**设置页若是独立进程**，进程内存兜底对主进程等于没存（我们用同进程窗口，不受影响）。

10. **打包漏依赖**（`BUILD-CI-FAILURE-NOTES-2026-08.md`、`ONEDIR_PACKAGING.md`）：参考项目反复出现"本机能跑、打包后缺资源"，如漏收集 `keyring`、`QtMultimedia`、`certifi`。**适用**：Electron 里是 `electron-builder` 的 `files` / `extraResources` / `asarUnpack`。**VRM 文件、音效文件、native 模块（如有）必须在打包产物里实测加载**，不能只在 `npm start` 下验证。参考项目的教训是"本地构建和 CI 必须共用同一份脚本"。

11. **代理 / VPN 对联网的影响**（`***.md`）：
    - 系统代理会让某些端点慢到超时（歌词取词直连 0.58 秒，走代理 41 秒），也会让某些端点只有走代理才通（jsdelivr 直连失败）。
    - 本地服务要保留 `localhost;127.*` 绕过。
    - **适用**：用户要用 DeepSeek（国内端点），Electron 的 `fetch` 默认走系统代理；若用户开了全局代理，对话会变慢。建议给"AI 设置"加一个"测试连接"按钮并在错误文案里写明可能是代理影响（参考项目的证书错误提示就是这个思路）。**开着梯子时 TLS 证书被拦截**会报证书错，参考项目给了"跳过 SSL 证书验证"的开关，我们个人使用可以考虑同样的逃生口，默认关。

12. **API 返回的错误文案**：代码里没有特殊处理 402/429，只显示 HTTP 状态和服务端原文。参考项目的做法是把常见状态码解释放在 README。**适用**：我们可以在错误气泡里直接映射常见 HTTP 码到一句人话（401 → 检查 Key，402 → 余额不足，429 → 稍后再试），这比参考项目做得更好，成本很低。

13. **异步写盘 + 退出时丢数据**：参考项目会话写盘是异步线程队列，退出时需要 `flush`，且 writer 被永久关闭后的写入要"拒绝可观测"（返回 False 并记日志）。**适用**：Electron 里用 `fs.promises.writeFile` + rename 原子替换，**`before-quit` 里等待未完成写入**，否则流式回复刚结束就退出会丢最后一条消息。

14. **模态弹窗在无人值守环境挂起**（`BUILD-CI-FAILURE-NOTES-2026-08.md`）：测试里弹出模态框会永久阻塞。**适用**：Electron 的 `dialog.showMessageBox` 同理，门禁（无头）里不要触发。

15. **"同一逻辑在两处读不同作用域的配置"是最高频的失败模式**（`INDEX.md` 对 v4.3.4 的总结）：设置里开着不生效、换音色没变，大多是这个原因。**适用**：我们的设置只有一份，但"主进程读配置 vs 渲染进程读配置"仍可能出现不同步，建议**配置只由主进程持有，渲染进程通过 IPC 取，改动时广播**。

16. **"调用成功"冒充"交付成功"**（同上）：待办、报时、节日气泡被另一条气泡占用时，参考项目曾把它当成功并盖戳，用户永远看不到。**适用**：待办/报时这类提醒要在**确认气泡真的显示**后才标记已触发。
